## Input parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `query` | string | — | Job title, role or skill to search for (e.g. "delivery boy", "telecaller", "accountant"). To browse the whole job feed instead, leave it empty and tick Browse All Jobs, or set a city or category filter. Use a JSON array for several searches in one run. |
| `location` | string | — | Optional. Keep only jobs in this Indian city, state or area (e.g. "Hyderabad", "Maharashtra", "Noida"). Matched against the city, state and area of each job. Use a JSON array for several locations. |
| `browseAll` | boolean | `false` | Browse the whole apna.co job feed instead of searching for a term. Combine with city, category or date filters to narrow it. Also used when the search term is left empty and a city or category filter is set. |
| `cities` | array | `[]` | Optional. Keep only jobs in these cities (common names like Bangalore, Gurgaon or Delhi are matched to apna's spelling). Combined with City / State. |
| `categories` | array | `[]` | Optional. Keep only jobs whose apna category, department, role or listing tag matches any value, e.g. "delivery-driver-logistics", "Accounts / Finance", "telecaller", "work-from-home", "10th-pass". Leave empty for every category. |
| `jobTypes` | array | `[]` | Optional. Keep only jobs whose job type or work mode matches any value, e.g. "Full Time", "Part Time", "Work from Home", "Field Job". |
| `educationLevels` | array | `[]` | Optional. Keep only jobs whose education requirement matches any value, e.g. "10th Pass", "Graduate". |
| `shifts` | array | `[]` | Optional. Keep only jobs whose shift matches any value, e.g. "Day Shift", "Night Shift". |
| `dateWithinDays` | integer | `0` | Keep only jobs posted within this many days (e.g. 1 for a daily feed). 0 = no date filter. Jobs without a published posting date are dropped when this is set. |
| `maxResults` | integer | `100` | Maximum total results (0 = unlimited). |
| `startUrls` | array | `[]` | Paste raw search URLs from the target site. Each URL becomes its own search task; results are merged and deduped by job ID across all URLs. When provided, startUrls REPLACE the query/location fields (each supported URL becomes one task; unsupported URLs are skipped, and if none is supported the run stops with an input error). |
| `includeDetails` | boolean | `true` | Fetch full job details. |
| `descriptionMaxLength` | integer | `0` | Truncate description to N chars. 0 = no truncation. |
| `compact` | boolean | `false` | Core fields only (for AI-agent/MCP workflows). |
| `excludeEmptyFields` | boolean | `false` | Drop null / empty-string / empty-array fields (and fully-null nested objects like socialProfiles) from each output record. Off by default to preserve dataset schema compatibility; turn on to slim output for LLM / agent consumption. |
| `enrichEmails` | boolean | `false` | Looks up each employer's own website and reads its contact pages for publicly listed emails. Best-effort: many apna employers are small local businesses without a website. Billed per contact email found, never for misses. Adds time to the run. |
| `incrementalMode` | boolean | `false` | Compare against previous run state. stateKey is optional — defaults to a value derived from search inputs (queries, locations, startUrls, country) so different filter sets never share state. |
| `stateKey` | string | — | Optional. Stable identifier for the tracked search universe. Leave empty to auto-generate from search inputs. |
| `emitUnchanged` | boolean | `false` | Also emit jobs that have not changed since the last run (incrementalMode only). |
| `emitExpired` | boolean | `false` | Also emit jobs that have disappeared since the last run (incrementalMode only). |
| `emitBaseline` | boolean | `true` | Incremental mode only. ON (default): the first run returns every current match and remembers it. OFF: the first run only records what exists now and returns nothing, so later runs return only jobs that are new or changed after that point. |
| `skipReposts` | boolean | `false` | When incremental, skip jobs whose content matches an expired job from a prior run (cross-run repost detection). |
| `notifyOnlyChanges` | boolean | `false` | When Incremental Mode is on, only send notifications for NEW and UPDATED jobs. Has no effect outside incremental mode. |
| `notificationLimit` | integer | `5` | Maximum number of jobs included in each notification message (1–20). |
| `telegramToken` | string | — | Telegram bot token (from @BotFather). Required for Telegram notifications. |
| `telegramChatId` | string | — | Telegram chat or channel ID (e.g. "-100123456789"). Required when telegramToken is set. |
| `discordWebhookUrl` | string | — | Discord incoming webhook URL. Server Settings → Integrations → Webhooks → New Webhook. |
| `slackWebhookUrl` | string | — | Slack incoming webhook URL. api.slack.com/messaging/webhooks. |
| `whatsappPhoneNumberId` | string | — | Your WhatsApp Business phone-number ID (numeric, from Meta dashboard). Required when whatsappAccessToken is set. |
| `whatsappAccessToken` | string | — | WhatsApp Cloud API permanent access token (System User token from Meta Business). Recipient must have messaged the business number within the last 24h (service-conversation window — free since Nov 2024). |
| `whatsappTo` | string | — | Recipient phone in E.164 format without + (e.g. "436641234567"). Recipient must have messaged your business number within last 24h. |
| `webhookUrl` | string | — | Receives a JSON POST with {metadata, items} after each run. Universal escape hatch for n8n / Make / Zapier / custom backends. |
| `webhookHeaders` | object | — | Optional JSON object of custom headers (e.g. {"Authorization":"Bearer ..."}). |
| `appConnector` | string | — | Optional. Pick a connected app under Settings → API & Integrations to receive your results (including any contact details). Best-effort across MCP connectors as Apify expands its catalog. |
| `mcpIssueTeam` | string | — | Only when the connected app is an issue tracker: the team (name or ID) the summary issue is created under, if that app requires one. |
| `descriptionFormat` | enum | `"all"` | Choose which representation of the listing description to include. `all` keeps every variant; the others keep only the selected one. |
| `lat` | number | — | GPS latitude of the search centre. Pair with lon and radiusKm to keep only jobs inside the radius. |
| `lon` | number | — | GPS longitude of the search centre. Pair with lat and radiusKm. |
| `radiusKm` | integer | — | Radius in kilometres around lat/lon. Only applies when lat and lon are both set; jobs outside the radius are dropped, jobs without published coordinates are kept. |
